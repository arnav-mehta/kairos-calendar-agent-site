What Kairos does

Kairos answers one practical question: when is there real availability after checking every calendar account, preference, buffer, and scheduling rule the user cares about?

Multi-account availability

Connect multiple Google and Microsoft accounts, then choose exactly which calendars count as busy.

Preference-aware suggestions

Use work hours, buffers, minimum notice, lunch blocks, priority tiers, and meeting placement rules.

Visual schedule review

Scan open windows, suggested slots, connected accounts, and calendar health from a compact dashboard.

  • Priority tiers High, regular, and low priority requests can use different defaults.
  • Preserve focus blocks Kairos can avoid splitting larger open blocks and prefer stacking meetings.
  • Meal-aware scheduling Breakfast, lunch, and dinner requests can be constrained to expected time windows.
  • Copy-ready formatting Availability can be copied as exact slots or consolidated windows.
  • One-click holds Suggested slots can be placed on a selected Google or Microsoft calendar as tentative holds.
  • Schedule from review Email requests can be converted into calendar invites from the chosen calendar account.

Email scheduling workflow

Kairos can work from pasted email text or from a dedicated scheduling inbox. The goal is to reduce back-and-forth while keeping the user in control.

1 Scan or paste

Read a scheduling email, including natural language such as proposed weekdays, date ranges, or meeting length.

2 Interpret the ask

Extract duration, date range, proposed windows, meal requests, reply recipients, and review confidence.

3 Check calendars

Compare candidate times or requested date ranges against the user's selected calendars and preferences.

4 Draft or send

Review, edit, send to sender, reply all, mark processed, or schedule an invite directly from the queue.

Beta user setup

A beta user receives the hosted app URL, their invited email, and an invite code. After signing in, they connect Google or Microsoft calendars, select calendars to include, and optionally connect a scheduling Gmail inbox for email-based scheduling.

1. Sign in

Use the invited email and invite code provided by the Kairos admin.

2. Connect calendars

Connect each Google or Microsoft account and select the calendars that should count as busy.

3. Start scheduling

Find openings, check proposed times, review scheduling emails, or install the PWA on mobile.

User checklist
  • Open the hosted Kairos app URL and sign in with the invited email and invite code.
  • Connect every Google or Microsoft calendar account that should be checked.
  • Open each connected account's calendar picker and select only the calendars that should count as busy.
  • Open Settings and set reply name, default duration, work hours, priority tier defaults, buffers, minimum notice, and daily avoid blocks.
  • Run Find openings once and confirm Calendar Health says the expected accounts and calendars were checked.
  • Optionally connect the scheduling Gmail inbox, then scan the inbox and review the generated drafts before sending.
Mobile install
  • On iPhone, open Kairos in Safari, tap Share, then tap Add to Home Screen.
  • On Android, open Kairos in Chrome, open the menu, then tap Add to Home screen or Install.
  • Sign in from the installed app with the same invited email and invite code.
  • Use the same hosted app for desktop and mobile. Calendar connections and preferences are shared for that invited user.

Admin and deployment setup

Kairos can run as an invite-only hosted PWA on a Node host with HTTPS and persistent storage. The current deployment path uses Render, provider OAuth apps, and encrypted per-user storage.

Required deployment pieces
  • Node web service running Kairos from the private GitHub repository.
  • Persistent disk or volume for encrypted user accounts, preferences, and processed email records.
  • Public HTTPS base URL for OAuth callbacks.
  • Strong random secrets for token encryption and signed Kairos sessions.
  • Invite list or admin-created invite records for beta users.
Provider setup
  • Google OAuth app with Calendar API and Gmail API enabled.
  • Microsoft Entra app registration with calendar read/write permissions.
  • Zoom OAuth app for meeting links once organization approval is available.
  • OAuth redirect URLs must exactly match the hosted callback URLs.

Access and privacy model

Kairos is designed for a private beta. Users sign in with an invite code, connect their own calendar accounts, and can revoke provider access through Google or Microsoft at any time.

  • Selected calendars only Users choose which calendars Kairos should consider.
  • OAuth-based access Calendar and inbox access is granted by the user's provider account.
  • Encrypted token storage Connected account tokens are stored encrypted by the app.
  • Lightweight status tracking Health checks store counts and warnings, not full calendar contents.
Current beta status

Kairos is not yet a public self-serve SaaS product. The current version is best for trusted beta users who are comfortable with invite-only access while OAuth verification and broader onboarding are refined.
